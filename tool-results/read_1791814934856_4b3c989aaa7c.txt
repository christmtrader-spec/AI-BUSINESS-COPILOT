   101→// Prompt 30 — email ownership verification (§4). ONLY the SHA-256 HASH of a
   102→// one-time verification token is stored; the raw token exists exclusively
   103→// inside the emailed link. Single active token per user is enforced in the
   104→// service layer (outstanding tokens are invalidated when a new one is issued,
   105→// §7). Purpose-separated from PasswordResetToken (§314/§315): a verification
   106→// token can never reset a password and vice versa.
   107→// ---------------------------------------------------------------------------
   108→model EmailVerificationToken {

   113→  expiresAt   DateTime
   114→  usedAt      DateTime?
   115→  requestedIp String?
   116→  userAgent   String?
   117→  createdAt   DateTime  @default(now())
   118→
   119→  @@index([userId, createdAt])
   120→  @@index([expiresAt])

   124→// Prompt 30 — TOTP MFA credential (§32). The TOTP secret is stored ENCRYPTED
   125→// (AES-256-GCM secret-box; key lives ONLY in the MFA_ENCRYPTION_KEY env var,
   126→// never in the database §33/§34). enabledAt NULL = pending setup (never

   128→// most one credential per user (§213).

   130→model MfaCredential {
   131→  id               String    @id @default(cuid())

   133→  user             User      @relation(fields: [userId], references: [id], onDelete: Cascade)

   136→  secretVersion    Int       @default(1)

   138→  // Replay protection state (§45): the last TOTP time-step accepted at login.
   139→  // A code from the same (or older) step can never be accepted twice. NULL
   140→  // until the first successful login after enrollment.
   141→  lastUsedTotpStep Int?
   142→  createdAt        DateTime  @default(now())
   143→  updatedAt        DateTime  @updatedAt
   144→
   145→  @@index([userId, enabledAt])
   146→}

   164→// ---------------------------------------------------------------------------
   165→// Prompt 30 — short-lived pre-auth MFA login challenge (§47). Password
   166→// success alone NEVER creates a session when MFA is enabled (§54): the
   167→// client receives only this bounded challenge. Hash-only storage; single
   168→// use claimed atomically (§50); bound to the user's sessionVersion so a
   169→// password change mid-challenge kills the challenge (§437/§438). The one-

   180→  attemptCount              Int       @default(0)
   181→  assertionHash             String?   @unique
   182→  assertionUsedAt           DateTime?
